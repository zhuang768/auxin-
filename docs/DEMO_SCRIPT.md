# 8 分鐘 Demo 腳本

目標：約 7 分 40 秒完成，留 20 秒緩衝。評審必須能親手操作。

## 0:00–0:45 問題

政府鼓勵青年使用 AI，但最危險的瞬間是把含個資的內容送出前一秒。既有宣導通常太晚，也與日常工具分離。

## 0:45–1:20 解法

展示首頁三層：本機防護、補助入口、市府工作台。讀出：「原始內容只在你的裝置上檢查，不會傳到竹青安心GO伺服器。」說明 LINE 只是可選通知。

## 1:20–4:10 評審親手操作（核心）

1. 開啟 `/demo-chat`（必要時先重設資料）。
2. 評審按「填入合成測試資料」或自行貼上 `testdata/demo_prompt.txt`。
3. 按送出。擴充功能攔截，列出類型與原因。
4. 評審選「安全遮蔽後送出」。
5. 畫面只送出改寫後內容。
6. 開啟 `/events`，指出欄位只有類別與動作，沒有原文。

若擴充功能未載入：改走備援，先載入 `extension/`，或展示已錄製畫面並改由主持人操作 Demo Chat。

## 4:10–5:00 教材

開啟 `/learning`，展示五步懶人包與一則有來源的案例，完成一題測驗。強調「教育就在行為發生時」。

## 5:00–6:00 市府流程

1. 青年端已有林小竹申請，或現場再送一筆。
2. `/admin/login` 以 Demo 帳密登入。
3. 將案件改為「開始審查」或「核准」。
4. 回到通知頁，青年看到站內通知。

## 6:00–6:40 LINE

在通知頁展示 LINE dry-run 預覽。清楚說：「LINE 為 PoC 通知介面，尚未連接新竹市政府正式帳號。」

## 6:40–7:20 成效與落地

匿名統計、最少資料、其他縣市可複用。完成憑證是 Demo 完整性證明，不是身分驗證。

## 7:20–7:40 收尾

竹青安心GO 不是叫青年不要用 AI，而是讓每一次使用多一個能理解、能選擇、又不必犧牲隱私的安全層。

## 失敗備援

- 本機 FastAPI + SQLite，不依賴外網。
- 第三方網站 DOM 失效時，只示範 Demo Chat。
- LINE 無 token 時，只展示 dry-run。
- 準備 60–90 秒錄影與本文件截圖路徑。

## 5 分鐘 Q&A 提要

- 為什麼不做 LINE Bot？風險發生在各 AI 工具，LINE 是通知轉接器。
- 有接政府 LINE 嗎？沒有。
- 正規表示式會誤判嗎？會，所以有檢核碼、解釋與覆寫。
- 如何證明沒偷傳 Prompt？API 拒絕原文，事件頁可當場看 schema。
- 憑證能防所有造假嗎？不能。
